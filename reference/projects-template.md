# PROJECTS.md 模板

放在项目总根（例如 `D:\Projects\PROJECTS.md`）。它只有一张表，别加别的。

```markdown
# 项目总图

> 更新于：2026-10-30 ｜ 进行中不超过 3 个

| 项目 | 一句话 | 状态 | 下一步 | 入口 |
|---|---|---|---|---|
| `demo-a` | 示例项目 | 进行中 | 补齐一批数据 | `demo-a/README.md` |
| `demo-b` | 第二个示例 | 暂停 | 等 demo-a 的数据 | `demo-b/README.md` |
| `demo-b` | 第二个示例 | 暂停 | 等条件齐了再开 | `demo-b/README.md` |
| `ppt-master` | PPT 生成工具 | 已完成 | — | `_archive/ppt-master/` |
```

## 五列怎么写

| 列 | 要求 | 反例 |
|---|---|---|
| 项目 | 目录名，加了反引号 | `项目1`、`新建文件夹` |
| 一句话 | 解决什么问题，不超过 20 字 | `各种资料` |
| 状态 | 只允许 `进行中` / `暂停` / `已完成` | `在做`、`快完了`、`TODO` |
| 下一步 | 一个具体动作，能今天就做 | `继续研究` |
| 入口 | 指向该项目的 README | 指向文件夹 |

## 三条维护规则

1. **每周扫一眼**：状态不对就改，别让它变成谎言。过期的总图比没有总图更糟。
2. **项目结束**：状态改 `已完成`，入口指向 `_archive/<项目>/`，整目录移过去。
3. **新项目**：先有目录和 README，再登记；不要先登记再建目录。

## 为什么"进行中"要限 3 个

不是纪律表演。同时推进 5 个项目时，你每天真正能推进的仍然只有 1~2 个，其余 3 个只是在消耗你的注意力。把状态改成"暂停"不是放弃，是承认现实——暂停的项目以后还能捡起来。

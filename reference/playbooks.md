# 场景手册

四个场景，照着做，别自由发挥。

## A. 新项目开工（10 分钟）

1. 起名：**语义名**，不要 `test`、`新建文件夹`、`项目2`。宁可长一点。
2. `hub.py init "<path>" --type <code|sim|data|doc>`。
3. 填 README 的「一句话」和「下一步」——填不出来说明项目还没想清楚，先别建。
4. `hub.py git "<path>"` 建仓库、提交第一次。
5. 到 GitHub 建一个 Private 空仓库，`--remote` 接上、`--push` 推上去（见 `git-github.md`）。
6. 把项目加进 `PROJECTS.md`。

## B. 一个项目已经乱了（30 分钟）

1. `hub.py map "<该项目>"` —— 先看，不动。
2. 只做三件事，按顺序：
   - 根目录散落文件归位（`check` 会列出来）；
   - `_tmp/` 里的东西：确认可弃就清空，不确定的留在原地；
   - 缺 README 就补一个，四句话即可。
3. **不做的事**：不重命名已有文件、不合并子目录、不重构目录树。那是第二次整理的事。
4. 整理完跑 `check`，然后停手。

**为什么只做三件事**：一次改太多，你会记不住自己改了什么，下次更不敢动。紊乱的目录最怕"大扫除"，最不怕"每次收一点"。

## C. 项目群出现一堆副本（proj / proj2 / proj3）

1. `hub.py map "<总根>" --dupes`，看清单。
2. 人工判断哪份是主干。判断依据按可信度排序：
   - 最近 30 天有更新的；
   - 有 README / git 记录的；
   - 文件数更多、更完整的那份。
3. 其余整目录移进 `_archive/`，**不删**。改 `PROJECTS.md` 的入口指向主干。
4. 主干目录改名：去掉数字后缀，换成语义名（`proj3` → `my-tool`）。改名前确认没有脚本硬编码该路径。

## D. 项目结束 / 搁置（10 分钟）

- **结束**：状态改 `已完成`，整个目录移到 `_archive/`，`PROJECTS.md` 的入口跟着改。
- **搁置**：状态改 `暂停`，目录不动。别为了"干净"去归档一个可能还会捡起来的项目——挪回去的成本比留着高。

## 每天收工（30 秒）

1. 在正在做的项目里跑 `hub.py save "<项目>"`。
2. 看到"已上传 GitHub"就关电脑；没传上去也不要紧，下次 `sync` 补一次。

别的都不用做。**没存档的改动等于没做过。**

## 每周例行（15 分钟）
1. 清空 `_inbox/`：每个文件要么归入某个项目，要么删掉。
2. 打开 `PROJECTS.md`，改状态和"下一步"。
3. 随机挑一个标着"进行中"但其实两周没动的项目，改成"暂停"。
4. 完事。**不要顺手开始整理某个项目**——那是另一件事，会吃掉你整个下午。
